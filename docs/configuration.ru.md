# Настройки, файлы и логи

[English](configuration.md) · **Русский**

Всё работает на **твоём** сервере с **твоим** ботом. Через серверы автора ничего не проходит: фото, токены и пароли никуда не уходят с твоих машин.

Проще всего менять настройки через `python3 setup.py` → меню. Эта страница — для тех, кто хочет знать, что внутри, и править руками.

## Где что лежит

При установке на VPS под root программа живёт в `/opt/proyavka`, на домашнем компьютере — там, куда ты её склонировал.

| Путь | Что это | Править? |
|---|---|---|
| `config.env` | все настройки бота (ниже) | да, потом перезапустить бота |
| `camera-config/config.txt` | файл настроек для приложения на Sony; бот присылает его по `/camera` | через мастер |
| `bot/filmbot.py` | бот, веб-сервер и всё, что ещё не вынесено | нет |
| `bot/proyavka/` | движок по модулям: `film.py` — плёнки (`PRESETS`), цвет, свечение, зерно; `imaging.py` — открытие кадров, кадрирование, засветы, дата; `config.py` — настройки; `i18n.py` — языки | `film.py` — да, см. [плёнки](films.ru.md) |
| `bot/webapp.html` | мини-приложение (один HTML-файл) | да |
| `relay/` | настройка сервера и приёмник кадров с камеры | редко |
| папка данных (`BASE_DIR`) | оригиналы, обработанные кадры, превью, база | нет |

Папка данных: `/var/lib/proyavka/data` на VPS, `~/proyavka-data` на домашнем компьютере. Кадры администратора лежат прямо в ней (`originals`, `work`, `views`, `thumbs`), кадры приглашённых — в `users/<id>/`.

## config.env

Одна строка — одна настройка вида `ИМЯ=значение`. После правки: `sudo systemctl restart proyavka-bot`.

| Настройка | По умолчанию | Что значит |
|---|---|---|
| `LANGUAGE` | ставит мастер | язык интерфейса: `en` или `ru` |
| `BOT_TOKEN` | — | токен от @BotFather |
| `CHAT_ID` | — | твой id в Telegram: ты администратор бота, остальных зовёшь через `/invite` |
| `WEBAPP_URL` | — | адрес мини-приложения, `https://<сервер>/` |
| `PROJECT_URL` | этот репозиторий | куда ведут ссылки на инструкции в `/camera` |
| `STORAGE_GB` | `20` | сколько места можно занять под твои кадры; сначала удаляются самые старые оригиналы |
| `USER_STORAGE_GB` | `5` | лимит для приглашённых; каждому можно поменять в `/users` |
| `DAILY_UPLOAD_LIMIT` | `300` | сколько кадров в сутки может прислать приглашённый (у администратора без лимита); `0` — без лимита |
| `COMMUNITY_URL` | GitHub raw `community/looks.json` | откуда сервер скачивает каталог плёнок сообщества (раз в час; копия лежит на диске и в репозитории). Пусто — только копия из репозитория |
| `COMMUNITY_REPO` | `Melnikoff07/proyavka` | репозиторий, куда ведёт «Предложить в каталог» (заявка); пусто — кнопки нет |
| `COMMUNITY_HUB` | `0` | `1` — этот сервер принимает плёнки от других: они ждут во вкладке «Сообщество» → «На проверке» (только у администратора), одобренная плёнка попадает в каталог, который сервер сам раздаёт по адресу `/community/looks.json` |
| `COMMUNITY_SUBMIT_URL` | — | куда «Автору» отправляет плёнку: `https://<приёмник>/api/community/submit`. Пусто на самом приёмнике — плёнки пишутся прямо в его очередь; пусто на другом сервере — кнопка уходит в Telegram / GitHub |
| `CONTACT_TG` | `Sashkere` | имя в Telegram для подвала альбомов и «⋯» → «О проекте»; в своём форке поставь своё, пусто — не показывать |
| `RAW_FILES` | `1` | принимать RAW (ARW, CR2/CR3, NEF, RAF, DNG, ORF, RW2…); включено по умолчанию, `0` выключает (`python3 setup.py --raw=0` или «Хранение и скорость» в меню). Мастер ставит библиотеку `rawpy`; если она не встаёт, RAW остаётся выключенным. Если камера шлёт RAW+JPEG, берётся JPEG, RAW выбрасывается |
| `MAX_MEGAPIXELS` | `120` | изображения больше отклоняются сразу — защита от «бомб», которые раздуваются в памяти |
| `CLEANUP_MINUTES` | `15` | как часто проверять лимиты места (после каждого приёма кадров — тоже) |
| `UPLOAD_MAX_MB` | `50` | предел одного файла, загружаемого через «+» в мини-приложении (тот же предел стоит в nginx) |
| `CHAT_PACE_SECONDS` | `1` | фоновые правки чата (пачки, удаление) — не чаще раза в столько секунд: так требует Telegram |
| `ORIGINALS_DAYS` | `14` | сколько дней хранить оригиналы; потом кадр можно смотреть, но плёнку уже не поменять |
| `MIN_FREE_GB` | `5` | сколько места на диске всегда оставлять свободным |
| `FAST_WORKERS` | ядер − 1 (не больше 3) | процессы для картинок в чат и превью |
| `HEAVY_WORKERS` | `1` | процессы для экспорта в полный размер |
| `WORKER_NICE` | `10` | приоритет обработки (больше — мягче к другим программам) |
| `WORK_EDGE` | `2560` | длинная сторона картинки в чате |
| `VIEW_EDGE` | `1600` | длинная сторона в мини-приложении |
| `FULL_EDGE` | `0` | длинная сторона «Файла»; `0` — полный размер камеры |
| `VPS` | `local` | куда приходят кадры: `local` (этот же сервер) или `user@host` (дом + VPS) |
| `SSH_KEY`, `REMOTE_DIR` | — | для варианта «дом + VPS»: ключ и папка приёма на VPS |
| `REMOTE_USERS_DIR` | `/srv/camera/u` | папки камер приглашённых пользователей на сервере-приёмнике |
| `SETTLE_SECONDS` | `15` | файл забирается, только когда не меняется столько секунд (запасной опрос) |

Лимиты можно задать и при установке: `python3 setup.py --storage-gb=0.1 --user-storage-gb=2 --daily-limit=100` (на уже установленном — сохранит и перезапустит бота).

Бот раз в 10 минут убирает на сервере-приёмнике то, что сам не забирает: RAW, не-фото и файлы во вложенных папках (старше 10 минут), недокачанное (старше 2 часов). Так по FTP нельзя забить диск мусором.

Строки в блоке `setup wizard` (`MODE`, `SERVER_IP`, `DOMAIN`, `CAMERA_TOKEN`, `FTP_PASS`…) нужны только мастеру. **Не публикуй `config.env`** — в нём твои токены и пароли.

## Службы и логи

| Служба | Что делает |
|---|---|
| `proyavka-bot` | бот, обработка и веб-сервер мини-приложения |
| `proyavka-recv` | приёмник для приложения на Sony (загрузка по HTTPS); токены приглашённых — хешами в `/etc/proyavka/camera-tokens` |
| `proyavka-tunnel` | только «дом + VPS»: туннель мини-приложения на VPS |
| `nginx`, `vsftpd` | HTTPS и FTPS для камер; FTP-логины — в `/etc/proyavka/ftp.passwd` (pam_pwdfile), у каждого своя папка |

Камеры приглашённых бот заводит и убирает сам: `sudo /usr/local/lib/proyavka/proyavka-user add|del u<id>`. Правило sudo (`/etc/sudoers.d/proyavka`) разрешает боту только этот скрипт.

```bash
sudo journalctl -u proyavka-bot -f        # лог бота в реальном времени
sudo systemctl restart proyavka-bot       # перезапуск после правок
systemctl status proyavka-bot proyavka-recv nginx vsftpd
```

Или `python3 setup.py` → «Состояние».

## Путь кадра

1. Камера кладёт файл в `/srv/camera/upload` на сервере (у приглашённых — в `/srv/camera/u/u<id>/upload`): FTPS с камер с FTP, HTTPS из приложения для Sony. Свои фото из телефона идут через «+» в мини-приложении прямо в бота.
2. Бот сразу это замечает (`inotifywait`), забирает файл и проверяет, что JPEG целый.
3. Выбирает плёнку (автоматически по сюжету или плёнку владельца по умолчанию), рисует версию для чата и отправляет в Telegram владельцу кадра.
4. Оригинал лежит в папке данных, пока хватает места и не прошло `ORIGINALS_DAYS`, — можно менять плёнку, силу, засветы и выгружать полный размер.
5. Удалённый кадр пропадает из ленты и чата, но файлы остаются в корзине: вернуть — `/trash` в чате. Когда место подходит к лимиту, первой чистится корзина (сначала давно удалённое), потом старые оригиналы.

## Попробовать плёнки без Telegram

```bash
.venv/bin/python bot/try_films.py photo.jpg            # лист со всеми плёнками -> photo_films.jpg
.venv/bin/python bot/try_films.py photo.jpg night800   # одна плёнка в полном размере
```

Удобно, когда подбираешь свою плёнку — см. [плёнки](films.ru.md).
